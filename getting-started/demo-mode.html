Demo Mode & Fixtures

k7s features an integrated Demo Mode (MockProvider) that runs the entire frontend in isolation without requiring a Rust compiler, a Tauri runtime, or a live Kubernetes cluster.

Why Demo Mode?

  • Rapid UI/UX Iteration: Work on CSS styles, layouts, animations, and component behavior inside standard web browser devtools (Chrome/Firefox/Safari) at http://localhost:1420.
  • Pixel-Fidelity Testing: Replays exact reference mock datasets matching the canonical design prototype (design/K8s Monitor.dc.html).
  • Zero Cluster Overhead: Great for presentations, demos, design reviews, or onboarding contributors who don't have local Kubernetes clusters configured.
  • Stress-Testing Engine: Simulate large-scale production clusters with thousands of synthetic pods to test virtualization and scrolling performance.

Launching Demo Mode

To launch demo mode in a browser:

# Standard demo mode
VITE_DEMO=1 pnpm dev

Open http://localhost:1420 (opens in a new tab) in your browser.

Stress Testing Virtualization

By default, demo mode loads 13 representative pods illustrating various Kubernetes lifecycle states (Running, Pending, CrashLoopBackOff, Completed, Terminating).

To test k7s under massive cluster load (such as 5,000 or 10,000 pods):

# Generate 5,000 synthetic pods
VITE_DEMO=1 VITE_STRESS=5000 pnpm dev

This exercises the virtualized table windowing algorithm (src/components/table/useVirtualRows.ts), proving that DOM nodes remain capped at ~40 rows and scroll frame rates remain pinned at 60fps.
